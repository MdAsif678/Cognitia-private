04 · Deep-Dive Architecture

How Cognitia Worked & Analyzed

A step-by-step breakdown of how this transaction was captured, simulated, and scored in real-time before MetaMask received it.

1

Page-Level In-DApp Interception

When the DApp called window.ethereum.request({ method: 'eth_sendTransaction', params }), Cognitia's Chrome extension Content Script intercepted the RPC invocation at the JavaScript provider layer before MetaMask or any browser wallet prompt could be triggered. The call was held in a pending lock state.

2

Ephemeral Chain Fork Simulation (Anvil RPC)

The intercepted payload was transmitted to the Cognitia Analysis API backend (http://localhost:8080/v1/analyze). The backend spawned an isolated transient Anvil Ethereum fork matching the current network state, executed the payload via eth_call & state trace overrides, and captured full pre/post state diffs, balance movements, and revert reasons.

3

Threat Database & Heuristic Risk Engine

The decoded calldata and state diffs were evaluated against the Swastik Risk Engine rule matrix. The engine performed signature matching against documented drainer DB address registries (Inferno, Pink, Angel Drainers), parsed EIP-712 typed data domains, and checked for dangerous exposure patterns (unlimited approvals, setApprovalForAll, permit zero-deadline exploit vectors).

4

Real-Time Sidepanel Signal & Decision Enforcement

The final verdict (HIGH RISK / CRITICAL / BENIGN) and security evidence were broadcast to the Chrome Extension Sidepanel via service worker messaging. The user is empowered to click Reject (canceling the call with standard RPC error code 4001 without opening MetaMask) or Continue to MetaMask.
